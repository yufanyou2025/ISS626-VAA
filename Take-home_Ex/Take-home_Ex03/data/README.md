# Input data and reproducibility

All access dates for this exercise are **1 November 2026**. The analysis uses January 2026 observed rail entries, completed HDB housing through 2025, the September 2026 official station-footprint file and pinned future-station coordinates. The future comparison holds the housing geography and total market fixed; it is a network scenario, not a forecast of housing completions or total future demand.

## Spatial inputs

Run `prepare-spatial.R` from the repository root. It downloads missing official HDB inputs and the pinned coordinate file, and uses the supplied Desktop `TrainStation_Sep2026.zip` when available. It verifies exact SHA-256 hashes before making analytical objects. Source URLs, vintages, licences, byte counts and hashes are in `outputs/spatial-input-manifest.csv`. If an upstream official dataset has changed, obtain the recorded snapshot; the script deliberately stops instead of silently changing the published results.

The two HDB sources do not share an address key: the geometry has a street code, while the property table has a street name. Joining by block number alone would mix addresses across towns. The bridge resolves this linkage. The analysis accepts spatial mappings with vote share at least 0.90, or block-set mappings with Jaccard similarity at least 0.80 and a lead over the next candidate of at least 0.50. Seven of 660 code mappings remain excluded; none contains an otherwise eligible residential block. Cantonment Road's bridge vote share of 0.8889 initially fails the threshold. I independently checked all seven residential blocks 1A-1G (postcodes 085101-085701) against official OneMap on 1 November 2026; every response confirms CANTONMENT ROAD. This documented override retains all 1,848 dwellings. The address evidence, exact queries and response hashes are in `data/reference/one-map-cantonment.csv`; no authentication field is retained. The final sample has **10,740 residential blocks and 1,167,327 dwelling units**, representing **100% of eligible property-table dwellings**. Exclusions and the empty unmatched-residential table remain explicit in `outputs/street-bridge-exclusions.csv` and `outputs/unmatched-residential-blocks.csv`.

Four invalid HDB source polygons are repaired with `st_make_valid()`. `st_point_on_surface()` produces a representative location inside each repaired building geometry. EPSG:3414 (SVY21 metres) is used for spatial operations. Distances represent straight-line access from representative building/station points, not walking routes or station-entrance access.

## Physical station definitions

The operating choice set comes from January 2026 observed `PT_CODE` values, not from the later footprint inventory. Thus depots, closed stations and stations absent from the observed month cannot enter just because their footprints exist. Slash-separated interchange codes form one physical station. Stevens is a source exception: separate `DT10` and `TE11` series are merged into `DT10/TE11`; `outputs/observed-station-crosswalk.csv` records this transformation. There are **181 existing physical alternatives**, from 182 observed codes.

The future scenario uses the brief's original **24 JRL line-station entries**, excluding the later `JS2A` Forest Hill addition, and **12 CRL phase 1 entries `CR2`-`CR13`**. It excludes CR1 and CRL phase 2. Seven future entries join existing physical stations: Choa Chu Kang, Boon Lay, Jurong East, Pasir Ris, Hougang, Ang Mo Kio and Bright Hill. These increase line connectivity and do not create duplicate nearby alternatives. The result is **29 new physical destinations and 210 alternatives in total**. `outputs/future-station-scope.csv` provides every original entry and its merged destination. Existing geometry remains the representative point at an expanded interchange.

`lines` and `line_count` both count distinct rail lines, not platforms. Circle Line branches count as the same line; the two directions/loops of an LRT system count as one line.

## Ridership input

The observed input is `data/raw/transport_node_train_202601.csv`: an LTA January 2026 station passenger-volume snapshot, retrieved on 1 November 2026 through a [pinned public third-party archive](https://raw.githubusercontent.com/tiredbeaver/busy-island/c13cb5943fea4a0118fc6b5b65a9eb923961e31f/data/transport_node_train_202601.csv), revision `c13cb5943fea4a0118fc6b5b65a9eb923961e31f`. It is not a current direct DataMall download, and has not been independently certified against the original January download. SHA-256 is `dedecc5f36b35583789b0fab24a7b02b0c3ec45c5e96b23e09b7d54656a841fa`. `prepare-ridership.R` downloads the exact public file and documents aggregation choices. The archive has 7,259 rows and 182 station codes, reduced to 181 physical sites by the Stevens merge. Weekday 06:00-09:59 tap-ins sum to 18,549,493 over 21 weekdays. No API credential is required and no token is committed. See `notes/ridership-provenance.md`. Do not substitute OD passenger pairs or tap-outs for station tap-in totals.

## Files created

`prepare-spatial.R` writes private working copies under `data/processed/`: `hdb-origins`, `existing-stations`, `expanded-stations` and `future-station-entries`, each as CSV and `sf` RDS. The script also creates the corresponding R objects `hdb_origins03`, `existing_stations03`, `expanded_stations03` and `future_station_entries03`. CSV coordinates include `x`, `y`, `lon`, `lat`; HDB weights are `dwelling_units`, and station keys are `station_id`. Audits and source manifests in `outputs/` are published.

Bulk raw files and intermediates stay out of Git and the public website. The **local submission ZIP includes five exact, licensed raw snapshots** for reproduction without future data updates: HDB Existing Building GeoJSON, HDB Property Information CSV, the station ZIP, the pinned station-coordinate CSV and the pinned January ridership CSV. `package_submission.py` checks their hashes against the published manifests before adding them and checks the archived copies afterwards. Small licensed bridge and official address-verification references are tracked normally. Caches, unused exploratory downloads, temporary scripts, signed download metadata and API authentication/error artifacts are excluded. The source project can also download the pinned inputs where available; its hash checks stop if a changing official dataset no longer matches the snapshot.
